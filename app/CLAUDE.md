# app/ Notes

- ⚠️ **Blank page / dead Generate button = corrupted `.next`, not a render bug.** Turbopack sometimes writes an empty React Client Manifest; the server still serves correct HTML (curl looks fine) but the browser throws a hydration error and the form becomes inert. Fix: `npm run dev:clean`. Diagnose by checking the **browser console**, not the server log. Full writeup in `docs/DEVELOPMENT.md` → Troubleshooting (moved there when `README.md` became the non-technical product overview).
- `app/global-error.tsx` exists partly as a workaround: Next 16 + Turbopack fails to resolve its *built-in* global-error module, so defining our own keeps that path off the table.
- ⚠️ **`app/globals.css` styles the browser form only and has nothing to do with the PDF** — the document's chrome and type are self-contained in `lib/chrome.ts` and measured against `docs/reference-letter-head.pdf`. Never propagate a token from one to the other; they answer to different references.
- **The browser UI is token-driven from `WEB_DESIGN.md`** (the frequency-extraction dump at repo root): every colour, radius, spacing step and type role in `:root` is transcribed from it, with variable names matching so the two can be diffed. Three deviations are documented in the file header — the `low-confidence` colour is unused (it fails the doc's own WCAG AA rule), Google Sans is unlicensable so it only leads the fallback stack, and elevation uses low-alpha white rather than invented hexes. Restyle by changing tokens, not by adding one-off values.
