# lib/ Notes

- **Module map**: `lib/escape.ts` (the single injection boundary) · `lib/schema.ts` (zod, shared client+server) · `lib/catalog.ts` (17 services, verbatim from `tools.md`, plus proposal-table `challenge`/`benefit` copy) · `lib/copy.ts` (fixed document prose) · `lib/view-model.ts` · `lib/brand.ts` (letterhead data URI) · `lib/chrome.ts` (letterhead layer + document CSS) · `lib/template.ts` · `lib/fonts.ts` (base64 inlining) · `lib/pdf.ts` (Chromium + timestamp pinning) · `lib/geometry.ts` · `app/api/generate/route.ts`.
- ⚠️ **`docs/reference-letter-head.pdf` is the finished proposal, not a letterhead swatch.** Its text layer decodes to the whole document — title, recipient block, intro, the three-column table, "Why Whaz", "Next Step". Every number in `lib/geometry.ts` and every margin in `lib/chrome.ts` is measured from that content stream. Treat it as the acceptance criterion; re-measure against it rather than adjusting margins by eye.
- **The letterhead is the approved raster, painted full-bleed** (`lib/brand.ts` → `assets/brand/letterhead.png`, 1054×1492, extracted losslessly from object `3 0 obj` of the reference PDF). It carries the header band, body watermark, and footer band as one image, so there is a single `.wz-letterhead` element. This replaced the earlier CSS/SVG band reconstruction — see the constitution's Principle II history before reverting.
- ⚠️ **Chrome repetition across pages needs TWO cooperating mechanisms** — remove either and multi-page output breaks silently. `position: fixed` *paints* the letterhead (Chromium repeats fixed elements per printed page); the `<table class="wz-doc">` with empty `thead`/`tfoot` *reserves* the vertical space. Body padding cannot reserve (applies only to page 1 → page 2+ content hides under the header band), and `@page` margins break fixed positioning outright. Both were tried and failed during implementation.
- **Body text is Arimo** (`assets/fonts/Arimo-*.woff2`), a metric-compatible stand-in for the reference's Helvetica. `@sparticuz/chromium` ships no system fonts, so Helvetica cannot be named and relied on. Sourced from `@fontsource/arimo` rather than Google Fonts, which serves Arimo variable-only.
- ⚠️ **Use static font files, never variable fonts.** Chromium converts variable fonts to Type3 in PDF output, which drops the ToUnicode map and breaks text selection/search on some pages.
- ⚠️ **Table margins compensate for Chromium's rounding, so don't "clean them up".** Values like `padding: 0.86mm` and `margin: 4.93mm` are not the reference's own numbers — a CSS margin runs between box edges while the reference's figures are baseline-to-baseline, and Chromium rounds the collapsed 0.4pt rules up to a whole device pixel. They were tuned until rendered baselines matched the reference to ≤0.11mm. Re-verify by rendering, not by reading.
- **Table cells must not wrap** — the reference has a uniform 6.35mm row pitch that only holds while every cell is one line. `npm run check:table-fit` measures every `challenge`/`benefit`/`name` in a real Chromium and fails if one would wrap. Run it after editing catalog copy.
- **Determinism required post-processing**: Chromium stamps `/CreationDate` + `/ModDate` at second resolution, so two renders a second apart differed. `lib/pdf.ts` pins both to the proposal date — the replacement must stay the same byte length, since PDF xref tables store absolute byte offsets.
- `clientCompany` and `proposalDate` are collected but never rendered: the first is the download filename slug, the second pins the PDF timestamps.
